Use case · MCP isolation

Tools that only exist
for the pinned tenant.

The MCP tool catalog is the isolation boundary: an unpinned session sees control tools only, and a pinned session sees that binding's provider tools and nothing else.

MCP wiring doc → Install
What the catalog enforces

  • Exclusive catalog. locus-mcp exposes Locus control tools and only the provider tools for the currently pinned binding; there is no ambient personal fallthrough.

    docs/mcp.mdAGENTS.md · invariants

  • Agents cannot pin. The model gets locus_request_pin only; pin state changes require the human CLI, and a request for a missing binding relays locus binding add, not enter.

    AGENTS.md · invariantscrates/locus-mcp/src/main.rs

  • Scope freeze. Frozen project_ref, team_id, and org/repo allowlists cannot be overridden by model arguments; provider-native aliases like projectId and owner are frozen too, and a mismatch fails closed.

    AGENTS.md · invariantscrates/locus-core/src/adapters/mod.rs

  • Supervised provider tools. A client-launched locus-mcp serves control tools only; the pinned binding's provider tools need locus mcp --supervised, which grants the active pin's executor capability and is audited as session.mcp.supervised.

    docs/mcp.md

  • No secrets over the wire. Tool results may show scopes and aliases, never resolved credential values, and locus-mcp stdout carries JSON-RPC only.

    AGENTS.md · invariants

  • Isolated child homes. Supervised children and spawned MCP workers get a scrubbed environment and an isolated HOME under the session worker dir, so gh and cloud CLIs see private config, not the user's.

    docs/mcp.mddocs/workers.md

  • Per-agent grants for swarms. locus serve --swarm graph.json serves each swarm agent only its explicitly granted MCP tools over the same multi-tenant transport.

    docs/swarm-broker.md
