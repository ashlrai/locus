Locus vs direnv
and sops.

direnv loads directory variables; sops decrypts a file into one command. Locus seals a session to one binding. Different jobs, and the repo ships a benchmark so you can check the numbers instead of trusting this page.

Method

All numbers on this page come from docs/BENCHMARKS.md, measured 2026-10-26 UTC on one Linux x86_64 machine (4 vCPU, 15.6 GiB): npm locus-cli 0.5.1 and git e969d9c4, direnv v2.38.2, sops v3.13.3 with age v1.3.2. Latency series are 21 runs with the first dropped.

Where each keeps identity

  • gh auth switch stores the active account in gh's shared hosts.yml; every process that reads that config sees the switch until the next one.

    README.mdgh manual

  • direnv exports only the variables in an allowed .envrc on cd; the rest of the shell's environment stays as it was.

    README.mddirenv.net

  • 1Password op run resolves secret references for one command.

    README.md1Password CLI docs

  • Locus binds the session to one binding: ambient GH_TOKEN, AWS_*, SUPABASE_* are scrubbed, a directory's .locus.toml can refuse other bindings, and MCP provider tools are only the pinned binding's.

    README.mdAGENTS.md · invariants
Takeaway

If the job is "put variables in this shell," direnv and sops are the right tools and the latency table shows they are faster at it. If the job is "this agent acts only as this tenant, and nothing ambient may leak into its children," that is what Locus seals, scrubs, and freezes.
